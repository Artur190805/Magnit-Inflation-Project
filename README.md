# Сбор цен продуктов магазина «Магнит»

Проект собирает цены с карточек товаров magnit.ru, сохраняет недельные значения и формирует индексную таблицу с числовыми ценами за килограмм или литр.

## Соответствие заданию

1. **Торговая сеть:** выбран магазин «Магнит».
2. **Товары и группы:** реестр содержит 53 товара, распределённых по 14 категориям.
3. **Ссылки:** все ссылки находятся в `products.toml`, внутри отдельных групп `[[groups]]` и `[[groups.products]]`.
4. **Сбор цены:** сначала используется цена конкретного товара из JSON-LD (`Product → offers → price`); резервный способ — связанная с ID товара структура Nuxt. Произвольная минимальная цена со страницы не выбирается.
5. **Единицы измерения:** цена фиксированной упаковки делится на достоверную массу или объём. Для товаров, продаваемых на развес и отмеченных `price_basis = "kg"`, цена считается за 1 кг. Если вес/объём невозможно подтвердить, нормированная цена остаётся пустой и товар попадает в `normalization_issues.csv` — выдуманные значения не подставляются.
6. **Недельная история:** для каждого товара хранится одна актуальная запись на неделю; повторный запуск в ту же неделю обновляет эту запись, предыдущие недели сохраняются.
7. **Индексный датасет:** `dataset_wide.csv` содержит `n`, дату, неделю и числовые столбцы `item_001` … `item_053`. Расшифровка столбцов находится в `items.csv`.
8. **Ограничение 1/4 МРОТ ±5%:** `basket_report.txt` подбирает набор из фактически собранных цен внутри целевого диапазона. Для упакованного товара учитывается одна упаковка, для взвешиваемого — 1 кг. Алгоритм максимизирует число представленных категорий, затем число товаров. Непродовольственные товары и корм для животных собираются, но не включаются в продуктовый набор.

**Уточнение методики корзины:** в исходных требованиях, которые были переданы для проекта, не указаны точные количества по каждому товару. Поэтому проект использует прозрачное правило «одна упаковка / 1 кг на развес» и подбирает допустимое сочетание товаров. Это расчётный учебный набор, а не официальный состав потребительской корзины. Если преподаватель отдельно задал веса/количества, их нужно внести вместо этого правила.

Федеральный МРОТ в конфигурации установлен в размере **27 093 руб.** с 1 января 2026 года (Федеральный закон от 28.11.2025 № 429-ФЗ). При изменении года проверьте актуальное значение и обновите `mrot_rub` в `products.toml`.

## Состав проекта

- `main.py` — основной скрипт сбора и обработки данных.
- `products.toml` — 53 ссылки, сгруппированные по 14 категориям.
- `requirements.txt` — необходимые сторонние библиотеки.
- `install.bat` — создание `.venv` и установка зависимостей.
- `run_weekly.bat` — запуск с записью журнала.
- `tests/test_main.py` — локальные тесты без обращения к сайту.

## Требования к компьютеру

- Windows 10/11.
- Python 3.11 или новее (проект проверяет синтаксис и TOML через стандартный `tomllib`).
- Доступ к интернету.

## Установка

Самый простой вариант — дважды щёлкнуть `install.bat`. Он создаст `.venv` (сначала попробует Python 3.12, затем 3.11) и установит зависимости.

Либо открой PowerShell в папке проекта и выполни вручную:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если `py -3.12` не найден, используй установленную версию Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Запуск

Из папки, где лежит `main.py`:

```powershell
.\.venv\Scripts\python.exe main.py
```

Или двойным щелчком по `run_weekly.bat`.

**Важно:** `main.py` и `products.toml` должны находиться в одной папке. Не запускай скрипт из другой копии проекта. До сбора скрипт проверяет, что в реестре ровно 53 записи; если файл обрезан или открыт не тот реестр, сбор останавливается и не перезаписывает результаты.

## Еженедельный запуск через Планировщик заданий Windows

1. Открой «Планировщик заданий» Windows.
2. Выбери «Создать простую задачу».
3. Название: `Сбор цен Магнит`.
4. Триггер: «Еженедельно», выбери день и время сбора.
5. Действие: «Запустить программу».
6. Программа: полный путь к `run_weekly.bat`.
7. В поле «Рабочая папка» укажи папку проекта.

Запуск вручную несколько раз в одну неделю не создаёт несколько недельных наблюдений: последняя успешная цена товара за текущую неделю заменяет предыдущую запись этой недели.

## Выходные файлы

| Файл | Содержание |
|---|---|
| `products.csv` | цены, полученные при последнем запуске |
| `price_history.csv` | история цен по товарам и неделям |
| `dataset_wide.csv` | индексная таблица с числовыми значениями руб./кг или руб./л |
| `items.csv` | соответствие `item_001` … `item_053` названиям и категориям |
| `basket_report.txt` | подбор продуктового набора относительно 1/4 МРОТ ±5% |
| `normalization_issues.csv` | товары, для которых не получилось подтвердить вес/объём |
| `parse_errors.csv` | ошибки загрузки или извлечения цены |
| `weekly_run.log` | журнал запуска через `run_weekly.bat` |

CSV записываются в UTF-8 с BOM, чтобы корректно открываться в Excel.

## Проверка проекта без интернета

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Локальные тесты проверяют структуру TOML, количество записей, извлечение упаковочных единиц, извлечение цены из JSON-LD и подбор набора в допустимом диапазоне. Они не заменяют сетевую проверку всех 53 карточек: доступность и цена на сайте меняются.
